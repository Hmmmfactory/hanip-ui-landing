# 편집실 업무·자동화 검토 결과

2026-09-07 기준. 코드, 현재 로컬 데이터, 원격 상태 응답, 모의 실행 및 실제 브라우저 화면을 점검했습니다.

## 1. 처음 맡는 사람의 업무 투입

판정: 자료 준비·검토 업무는 안내를 따라 시작할 수 있도록 개선했습니다. 실제 신규 담당자의 사용성 시험은 아직 하지 않았습니다. 주제에 관한 실제 경험을 대신 답하거나 승인 책임까지 자동화할 수는 없습니다.

| 발견한 문제 | 개선 |
|---|---|
| 버튼은 많지만 무엇부터 누를지 모름 | 전체 현황에 ‘첫 업무 열기’, 글별 현재 담당·다음 행동·이유 추가 |
| 무엇을 마치면 끝인지 모름 | 답변 → 사진 → 검수 → 승인 → 공개 확인 → 전달 확인 완료 기준 표시 |
| 질문을 끝까지 눌러봐야 범위를 알 수 있음 | 전체 질문 목록, 필수 여부, 저장 여부, 사진 안내를 미리 펼쳐보기 |
| 이전 질문·업무로 이동하면 입력을 잃을 수 있음 | 이전과 업무로 돌아가기 버튼도 현재 입력 저장 |
| 수정 답변이 원고에 반영되기 전에 검수 가능 | 새 원고는 반영 버전을 추적해 초안 보완을 먼저 요청 |
| 개발 관련 정보가 초안 독해 방해 | 내부 설정·주석·명시된 편집 메모·코드 블록을 제외한 본문 미리보기 |

첫 업무: 전체 현황 → 첫 업무 열기 → 담당자 지정 → 질문·사진 준비 → 초안 보완 → 본문 읽기 → SEO 검수 → 최종 승인 → 예약. 에이전트가 작업 중이면 기다리고, 새 신호가 90초 이상 없으면 기록을 확인합니다.

## 2. 발행 자동화·텔레그램

판정: 기존 원격 봇과 로컬 편집실은 별개였고, 처음 상태로는 발행·전달이 연결됐다고 볼 수 없었습니다.

- 원격 `/api/automation-status`는 200 응답과 `ready: true`, 07:30·10:00 일정을 반환했습니다. 그러나 저장소에 해당 시간의 실행기가 없었습니다. 환경변수 존재만 확인한 결과입니다.
- 원격 `/draft`는 실제 초안이 아니라 `posts.json` 첫 글을 ‘검토용 초안’이라고 전송했습니다. 코드에서 최신 등록 글과 로컬 초안 안내를 구분하고, 원격 예약 실행이 없다는 상태로 수정했습니다. **이 원격 API 수정은 아직 공개 배포하지 않았습니다. 현재 원격 응답은 종전 버전입니다.**
- 로컬은 승인된 글만 예약하고 공개 URL을 확인했지만 텔레그램 전달 연결이 없었습니다. 발행 후 제목·본문 발췌 요약·공개 링크 전달과 글별 이력을 추가했습니다. 요약은 본문 첫 유효 문단의 발췌이며 AI가 새로 작성한 요약은 아닙니다.
- 공개 확인을 제목만 확인하던 방식에서 본문 일부와 표시 규칙 식별자 확인까지 강화했습니다. 본문 전체의 의미적 동일성을 보장하는 검사는 아닙니다.
- 알림은 발행 상태와 독립적입니다. 연결 필요 / 전달 중 / 접수 확인 / 거절 / 결과 불확실을 구분합니다. 접수된 메시지 번호를 저장하며 이미 접수된 알림은 중복 전송하지 않습니다. 응답 끊김·재시작은 자동 재전송하지 않고 사람에게 확인을 요청합니다. Telegram 접수는 사람의 읽음 확인이 아닙니다.
- 기존 Vercel 로그인으로 연결 값을 재사용하려 했지만 Production 비밀값이 내보내기 불가여서 가져오지 못했습니다. 로컬 연결 키·대화 ID 입력, 메시지 없는 연결 확인, 자동 전달 켜기가 남아 있습니다. 키는 로컬 비공개 파일에 저장하고 화면·작업 기록으로 반환하지 않습니다.
- 원격 웹훅과 로컬 상태의 양방향 동기화, 텔레그램 채팅을 통한 승인·수정 명령, 휴대폰의 로컬 검토 화면 접근은 현재 제공하지 않습니다. 검토와 승인은 이 Mac의 브라우저에서 합니다.
- Mac과 편집실이 켜져 있어야 예약을 실행합니다. 6시간 넘게 지난 예약은 다시 정해야 합니다. 잠든 Mac을 자동으로 깨우는 기능은 없습니다.

연결 후 남은 실제 검증: 사용자가 승인한 실제 원고 1편의 예약 발행 → 공개 URL 확인 → 텔레그램 제목·요약·링크 수신 확인. 이번 점검에서 공개 발행이나 실제 메시지를 보내지는 않았습니다.

## 3. 본문 표시 규칙

글별 ‘블로그 형태로 읽기 · 줄바꿈과 강조 설정’에서 선택합니다.

- 줄바꿈: 문단 중심 자동 줄바꿈 / 원문 줄바꿈 유지
- 문단 간격: 촘촘하게 / 편안하게 / 넉넉하게
- 강조: 원고에 지정된 강조 구절을 굵게 / 배경 강조 / 강조 없음

선택 즉시 화면에서 미리 볼 수 있고 저장해야 적용됩니다. 변경하면 기존 검수·승인·예약을 해제합니다. 같은 렌더러로 발행 담당에게 전달할 본문과 스타일을 준비합니다. 실제 발행물에서는 설정 식별자도 확인합니다. 확인이 필요한 경험 문구는 숨기지 않고 남겨 발행 전 보완하도록 합니다. 이 기능은 서식 설정이며 문장 자체를 고치는 본문 편집기는 아닙니다.

## 검증 범위

- 로컬 자동 테스트: 원고 조회, 요청 보호, 작업 대기열, 재시작, 답변, 예약, 승인 변경, 사진, 렌더링, 발행 검증, 텔레그램 성공·거절·불확실·중복 방지.
- 실제 브라우저: 첫 업무에서 글별 안내와 독자용 미리보기 진입, 문단·목록·링크·강조 설정 표시 확인.
- 기존 초안 5편과 질문 답변은 보존했습니다. 공개 배포·실제 발송 결과는 미검증입니다.
