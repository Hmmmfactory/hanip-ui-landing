# B01 편집실

로컬 전용 블로그 관리 화면. Node.js 20 이상과 로그인된 Codex CLI가 필요합니다. 추가 패키지 설치는 없습니다.

```sh
node local-console/server.mjs
```

http://127.0.0.1:4317 에서 엽니다. Mac 재시작 후에는 다시 실행해야 합니다. 포트 충돌 시 `EDITORIAL_PORT=4318 node local-console/server.mjs`를 사용합니다.

Finder에서 `편집실 열기.command`를 더블클릭하면 Mac의 기본 브라우저에서 열립니다. 실행 중인 편집실이 있으면 재사용하고, 없으면 백그라운드로 시작합니다. 이 실행 파일로 시작한 경우 터미널 창은 닫아도 됩니다. Mac은 켜져 있어야 합니다. 데스크톱 앱에 포함된 Codex 실행 파일을 우선 사용하며, 없으면 PATH의 `codex`를 사용합니다. 특정 실행 파일은 `EDITORIAL_CODEX_BIN`으로 지정할 수 있습니다.

## 사용

- 전체 현황: 등록 글, 초안, 남은 글감, 진행 작업과 최신 활동.
- 글과 요약: 저장된 summary와 본문, Markdown 초안, 실제 글감 목록.
- 사이드바: 편집장 / 작가 / SEO 검수 / 발행 담당. 선택하면 명령 창이 열립니다.
- 명령은 기본 읽기 전용입니다. 초안 작성·수정은 작업 범위에서 파일 변경을 허용하세요.
- 작업 상태는 3초 간격으로 갱신됩니다. 동시에 파일을 수정하지 않도록 한 번에 한 작업을 실행합니다.
- 종료된 작업의 ‘이 결과로 이어서 요청’은 이전 요청과 최종 결과를 새 실행에 전달합니다. 전체 Codex 대화의 재개는 아닙니다.
- 작업 중단은 실행 프로세스 그룹에 종료 신호를 보냅니다. 이미 적용된 파일 변경을 되돌리지는 않습니다.

## 주간 업무 흐름

1. **주간 발행 계획**에서 월요일을 선택하면 글감 7개가 준비됩니다. 평일은 가구 생활 이야기, 토요일은 취미, 일요일은 소비·예산입니다. 반복 템플릿이므로 새 주마다 기존 글과 겹치지 않도록 제목·방향을 조정하세요. 에이전트도 최근 글을 확인합니다.
2. **초안 최대 5개 미리 준비**는 아직 초안을 요청하지 않은 글 최대 5개를 순서대로 작성합니다. 하루 한 편 제한은 없습니다. 주말 두 편은 개별 초안 요청 또는 다음 배치로 준비하세요.
3. **내가 할 일**에서 담당 글의 질문 수, 사진 안내, 다음 행동을 확인합니다. 질문 답변은 한 단계씩 저장합니다. 추가 질문이 발생하면 총 질문 수에 포함됩니다.
4. 질문·사진을 준비한 뒤 **초안 보완 → SEO 검수**를 요청합니다. 원고가 바뀌면 검수와 승인도 다시 필요합니다.
5. 최신 원고의 검수 13항목에 실패가 없고 필수 질문과 사진 선택이 완료되면 **발행 승인 → 예약 발행 설정**을 할 수 있습니다. 예약 버튼은 실제 공개 발행 실행을 승인합니다.

진행 단계는 Codex의 PROGRESS/DONE 메시지로 갱신됩니다. 경과 시간만으로 단계를 완료시키지 않습니다. 90초간 신호가 없으면 확인 안내가 표시되며, 이것만으로 중단을 확정하지 않습니다. 기존 작업에는 단계 기록이 없을 수 있습니다.

예약은 한국 시간 기준이며 로컬 서버가 15초마다 확인합니다. Mac과 서버가 켜져 있어야 합니다. 6시간 이내의 놓친 일정은 재시작 시 실행하고, 6시간을 넘기면 다시 일정을 정하도록 표시합니다. 예약 실행은 Codex 발행 담당이 기존 Vercel 연결을 사용합니다. CLI 인증·네트워크·배포 권한 문제는 글에 실패로 표시합니다. 예약 발행 전체를 실제 공개 배포로 시험하지는 않았습니다.

발행 완료는 반환 URL, 로컬 canonical과 실제 공개 응답의 제목을 확인한 뒤 표시합니다. 준비된 로컬 파일만으로 발행 성공을 표시하지 않습니다. 사용자 정의 도메인은 현재 자동 확인 경로에서 지원하지 않아 수동 확인이 필요합니다.

추가 데이터: `.editorial-console/workflow.json`, `.editorial-console/uploads/`. 사진은 PNG/JPEG/WebP, 장당 6MB, 글당 6장입니다. 개인 Mac의 단일 사용자 도구이며 팀 계정 인증이나 동시 편집 권한 기능은 포함하지 않습니다.

## Codex 안에서 명령하기

프로젝트의 AGENTS.md가 다음 명령을 안내합니다. 사용자가 “편집실 진행 상황 확인해줘”, “편집실 작가에게 초안 요청해줘”라고 하면 Codex가 이 도구를 실행할 수 있습니다.

```sh
node local-console/cli.mjs status
node local-console/cli.mjs tasks
node local-console/cli.mjs send editor "최근 글과 남은 글감을 요약해줘"
node local-console/cli.mjs send writer "생활 이야기 초안을 작성해줘" --write
node local-console/cli.mjs cancel TASK_ID
```

브라우저는 설치된 `codex exec --json`을 호출하고 기존 ChatGPT 로그인을 사용합니다. 현재 데스크톱 대화에 메시지를 삽입하거나 다른 모든 대화를 수집하지 않습니다. 두 입력 경로가 **편집실의 작업 큐와 결과를 공유**하는 구조입니다. 모든 역할은 사용자가 설정한 Codex 모델을 사용하며, 서로 다른 역할 지침을 받습니다.

## 데이터와 범위

원본은 `story/posts.json`, `story/ideas.md`, `story/drafts/*.md`. 작업과 연결 정보는 Git에서 제외한 `.editorial-console/`에 저장됩니다. 손상된 작업 파일은 자동 덮어쓰기 하지 않으므로 백업 후 복구하세요. 재시작 시 진행·대기 작업은 중단으로 표시하며 자동 재실행하지 않습니다.

페이지 준비 수는 로컬 HTML 존재 여부입니다. 라이브 발행 성공, 방문자 수, 예약 발행을 의미하지 않습니다. 공개 배포는 사용자 명령에 명시되어야 하며 실제 결과 확인이 필요합니다. 서버는 127.0.0.1에서만 듣고 호스트·Origin·변경 요청 토큰을 검증합니다. 비밀 파일과 프로젝트 전체를 정적 제공하지 않습니다.

WebMCP 지원 브라우저에는 상태 읽기와 명령 작성창 열기를 제공합니다. 일반 브라우저는 같은 UI/CLI로 사용합니다. WebMCP 실브라우저 검증은 수행하지 않았습니다.

## 독자용 초안과 전달 확인

글별 **블로그 형태로 읽기 · 줄바꿈과 강조 설정**에서 내부 설정을 제외한 본문을 읽고 글별 줄바꿈·문단 간격·강조 규칙을 저장합니다. 설정 변경은 검수와 승인을 해제합니다. 발행 담당에게 같은 본문/스타일을 전달하고 공개 본문 일부와 표시 규칙을 확인합니다.

전체 현황의 **연결과 전달 상태 확인**에서 Telegram 봇 키와 받는 대화 ID를 로컬에 저장하고, 메시지 없는 연결 확인 후 자동 전달을 켭니다. 공개 발행이 확인된 뒤 제목·본문 발췌 요약·공개 링크를 전송합니다. 키는 `.editorial-console/telegram.json`에만 보관합니다. 기존 원격 봇과 초안·승인 상태를 동기화하지 않으며 웹훅을 변경하지 않습니다. 발송 실패나 결과 불확실은 글별 전달 상태에 표시되고 자동 중복 재시도하지 않습니다.

운영 검토와 남은 실제 확인 사항은 `검토-보고서.md`에 기록했습니다.

## 검토 완료 후 1시간 발행 정책 (2026-09-08)

사용자 요청으로 1시간 발행 정책을 켰습니다. 검수 통과와 필수 자료 확인을 마친 원고에 텔레그램 발행 확인 메시지를 보냅니다. 메시지 접수 확인부터 1시간 이내 브라우저의 ‘지금 발행’을 누르면 즉시 발행하고, 응답이 없으면 한 번 자동 발행합니다. ‘보류’ 또는 원고 변경은 자동 발행을 막습니다. 예전 검수 시각을 소급해 즉시 발행하지 않습니다.

현재 발행·보류 버튼은 로컬 편집실에 있습니다. 기존 원격 봇의 Telegram 승인 버튼과는 아직 연결되지 않았습니다. Telegram 연결 정보가 없거나 접수 결과가 불확실하면 타이머를 시작하지 않습니다. 발행 성공/실패는 별도로 Telegram에 보고합니다. Mac과 편집실이 실행 중이어야 하며 잠자기 중에는 실행되지 않습니다. 기존 Codex ‘B01호 매일 오전 10시 조건부 발행’ 자동화는 중복 발행을 막기 위해 일시 중지했습니다.

## 자동 보완과 원격 발행 판단 (2026-09-10)

사용자가 요청한 자동 보완·검수는 `/api/workflow/editorial-policy`로 켭니다. 기존 초안에 저장된 답변을 반영하고 SEO 검수를 실행합니다. 원고 버전당 보완은 최대 두 번이며 해결하지 못하면 `autoBlocked`로 표시합니다. 새 답변으로 버전이 바뀌면 다시 진행합니다. 실패한 실행은 자동 재시도하지 않습니다. 사진이 없고 사용 여부가 미정이면 사진 없이 검토합니다. 검수 통과는 사람의 승인을 기록하지 않습니다.

텔레그램 `remoteApproval`은 전용 봇의 개인 대화에서만 사용합니다. 기존 웹훅은 삭제하지 않고 충돌 시 차단합니다. getUpdates로 받은 버튼은 수신 대화·누른 사람·현재 메시지 ID·원고 해시를 확인하며 중복 클릭은 다시 발행하지 않습니다. 수신 실패 시 자동 발행보다 보류 확인을 우선합니다. API 기준: https://core.telegram.org/bots/api#callbackquery

자동 편집 모드에서는 원격 발행·보류 연결 전까지 발행 알림 타이머를 시작하지 않습니다. 설정과 실제 Telegram 송수신 검증은 별개입니다. Mac과 서버가 실행 중이어야 원격 선택을 처리합니다. 과거 README의 ‘콜백 미연결’ 설명은 이 코드 변경 전 상태입니다.

## 브라우저 접속 복구와 지속 실행 (2026-09-11)

접속 실패 당시 4317 포트의 수신 프로세스가 없었습니다. 기존 실행은 Codex의 임시 실행 프로세스 또는 nohup에 의존했고 로그인 자동 실행·종료 후 복구 서비스가 없었습니다. 기존 로그에는 시작 메시지만 있어 과거 종료 시각과 종료 원인은 확정할 수 없습니다.

`편집실 열기.command`는 이제 `service.mjs`로 사용자 LaunchAgent `com.b01.editorial-console`을 등록하고 정상 API 응답을 기다린 다음 기본 브라우저를 엽니다. macOS 로그인 시 자동 시작하고 서버 종료 시 다시 실행합니다. 실행 파일 경로는 절대 경로이며 로그는 `~/Library/Logs/B01/editorial-console.log`에 저장합니다. 서비스의 작업 디렉터리는 사용자 홈이고, 앱은 자체 경로를 기준으로 저장소를 읽습니다. 초기 등록 중 프로젝트 디렉터리를 서비스 작업·로그 경로로 지정한 설정에서 EX_CONFIG가 발생해 이 배치를 수정했습니다.

- 접속: http://127.0.0.1:4317/
- 열기/서비스 복구: `zsh 'local-console/편집실 열기.command'`
- 서비스 중지: `node local-console/service.mjs stop` (다시 열거나 다음 로그인 시 재시작)
- macOS 설정에서 이 백그라운드 실행을 끄면 자동 실행되지 않습니다.
- Mac 전원 꺼짐·로그아웃·잠자기 동안 작업은 실행되지 않습니다. 브라우저 창이나 터미널만 닫는 것은 서비스를 중지하지 않습니다.
- 실제 검증: 화면/API 응답, Codex 인증, 서비스 프로세스의 launchd 관리 상태와 작업 없는 상태에서 종료 후 자동 복구를 확인합니다.

## 텔레그램 승인 후 발행 (2026-09-11 변경)

`publicationPolicy.requireTelegramApproval: true`이면 1시간 자동 발행은 실행하지 않습니다. 알림 접수 뒤 deadline은 없으며 본인의 현재 메시지 버튼으로 승인해야 발행합니다. 브라우저의 publish-now 요청도 거절합니다. 보완·재검수는 그대로 자동 진행합니다. 원격 승인 수신에는 Mac이 실행 중이어야 합니다.

연결 화면 바로가기: http://127.0.0.1:4317/#telegram
로컬에 저장된 배포 환경의 Telegram 값은 검사 당시 유효한 키·대화 ID 형식이 아니었고 getMe는 404였습니다. 기존 봇의 동작 중단을 입증한 것은 아닙니다. 유효한 키를 비공개 연결 화면에서 저장한 뒤 봇 신원·기존 웹훅을 확인해야 합니다. 기존 웹훅은 자동 삭제하지 않습니다.
